# 面试 15 问（围绕本作品）

用自己的话答。数字以你本地 `python -m app.eval_runner` 为准。

1. **这不是 Chatbot 吗？**  
   短厅是封闭动作空间。主路径是规则引擎 + 确认门 + 工具，模型只做未命中时的意图分类。

2. **为什么不让模型直接 function call 办理？**  
   关停/订购有法务和客诉成本。模型可以提议 intent，执行权在策略层。注入「跳过确认」不能生效。

3. **和你现在的 see 引擎有什么关系？**  
   see 做精确匹配和会话；本作品在未命中处加了一层意图识别。现网可以先做影子模式，只记日志不办理。

4. **准确率怎么来的？**  
   `data/eval_set.json` 分层：规则 / 确认 / 套餐限制 / 口语 / 安全 / 菜单。看 intent、tools、是否误办理。

5. **启发式和 LLM 怎么选？**  
   无 Key 或超时走启发式，保证 Demo 和降级。上线以 LLM 为主、规则为盾。

6. **RAG 在这里解决什么？**  
   配置助手要引用制度；用户侧口语可能依赖套餐说明。检索是给分类器约束，不是把文档贴进短信。

7. **短信长度怎么处理？**  
   中文 UCS-2 单条 70 字，超长拆分。约束在输出层，不指望模型数格子。

8. **预付后付如何隔离？**  
   policy 按 intent 限制套餐。后付暂停数据直接拒绝，不进入确认，避免用户以为能办。

9. **如何避免编造余额？**  
   查询必须走 `get_balance`。评测里「编一个余额」期望 `out_of_scope` 或不调用成功办理。

10. **配置 Copilot 和一站式隐性指令需求的关系？**  
    现网痛点是多系统多表。作品里指令草案只映射已有意图；新业务要接口描述+出入参生成意图，人审后写配置。多接口办理（资费列表）在引擎里用 2way 编排 Mock BOSS，不让模型自己选下一步调哪些接口。

11. **上线最大风险？**  
    误办理、越权查询、费用失控、延迟导致会话过期。所以要影子流量、确认门、预算熔断。

12. **为什么 Java 主业却用 Python 做作品？**  
    落地常见形态是 Python 推理层 + Java 业务层。你能讲两边如何划界：Java 继续做网关/会话/办理，Python 只出 intent。

13. **Agent 什么时候才用？**  
    配置生产这种多步、可回滚、人工审核的草稿流程。用户办理主路径是状态机；列表「第一个 / 50G本地流程」只做约束内对齐。关键词命中多项时缩小列表并保留原编号，不让模型擅自订第一项。

14. **简历怎么写这个项目？**  
    「运营商短信营业厅智能办理：规则优先的意图路由 + 二次确认 + 评测集。敏感操作误执行率 0。」不要写内部系统名。

15. **你下周还要补什么？**  
    接真实 LLM 对比正确率、扩评测集、trace 费用上限、录 Demo。按 PLAN.md W3–W6。
