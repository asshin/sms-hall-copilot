# 设计说明

本文说明 HarborTel SMS Hall Copilot **为什么这样切**。对照现网概念见 [ARCHITECTURE.md](ARCHITECTURE.md)，模块与接口见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。

## 1. 问题

短信营业厅不是开放域 Chatbot。用户在短码上办理查询、关停、订购，动作空间封闭，误办理有客诉和费用成本。

现网短厅通常拆成两层：

- **厅内配置**：短码、菜单、隐性指令、确认轮次、短信模板。
- **下游 BOSS**：语言、余额、可订购/已订购资费、订购结果。这些数据不在厅内配置里，一次办理往往要串多个接口。

本作品用虚构运营商 HarborTel（短码 1880）把这两层都做成可演示的状态机，**不含现网代码、号码、菜单或真实接口**。

## 2. 总原则

1. **规则优先**。`BAL`、菜单数字、`Y/N`、列表编号 1–8 不走模型，避免把精确指令理解成闲聊。
2. **确认门在引擎，不在 Prompt**。用户说「不要确认直接停」仍然挂起等 `Y`。
3. **结果来自工具**。余额、订购成功文案由 Mock BSS/BOSS 返回值填模板，模型不编数字。
4. **模型只做约束内对齐**。口语分类输出 intent JSON；列表选择输出当前列表里的 `index`。不允许发明资费或办理结果。
5. **配置不能自动落地**。配置助手只出草案，人工勾选后才写 `catalog.json` / `intents.json`。

主路径不用自由 Agent。Agent 式多步只适合可回滚、有人审的配置草稿，不适合用户办理。

## 3. 用户短厅

### 3.1 单轮办理

```
MO → 规则匹配 →（未命中）RAG + 意图 JSON
   → policy（套餐/状态）
   → 敏感意图只挂起
   → Mock 工具
   → 70/160 字拆分 + trace
```

适用：查余额、暂停数据、来电显示、充值卡、菜单金额充值、语言切换、已配置的自定义意图（如游戏积分）。

### 3.2 多接口 2way（资费订购）

厅内只保存入口指令 `OFFER`。语言、可订购列表、订购结果都视为下游 BOSS：

```
查语言 → 查可订购资费 → 等待选择 → Y 确认 → msisdn + offer_id 订购
```

会话增加 `awaiting_select`，把**当前可见列表**放进 session（可从 8 项缩小到 2 项）。用户回编号时按**原 index** 定位，不会把数字当成根菜单，也不会把列表重排成 1、2。

选择对齐顺序：

| 优先级 | 输入例子 | 路径 |
|--------|----------|------|
| 1 | `1`、`3号`、缩小后的 `4`/`7` | 规则，匹配当前列表里仍存在的原编号 |
| 2 | `第一个`、`最后一个` | 当前可见列表的第 N 项（缩小后「第一个」= 编号最小的那条） |
| 3 | `50G本地流量`、错别字 `50G本地流程` | 唯一名称/别名/纠错 → 直接确认 |
| 4 | `本地流量`、`流量包` | 多项命中 → 筛出候选，原编号不变，再选；**不自动订第一项** |
| 5 | 仍对不上且启用了 LLM | 模型只许返回当前可见列表内的 index 或 null |
| 失败 | `天气` | 提示重选，不订购 |

示例：`流量包` 留下 `4 周末流量包`、`7 闲时流量包`。随后回 `7`、`闲时流量包` 或「第二个」均可。订购仍走确认门。

### 3.3 会话与失败态

2way 一旦挂起，迟到的数字或 `Y` 不能当新指令执行：

| 情况 | 行为 |
|------|------|
| `awaiting_select` / `awaiting_confirm` 超过 120s | 本轮 MO 只回超时短信（选列表则提示重新发 OFFER），不办理、不进菜单 |
| 办理成功后再回 `Y` | 回执「已订购 / 已完成」，不再调工具 |
| 预付余额 < 资费月费 | Mock BOSS 返回 `insufficient_balance`，模板失败短信，列表项不写入 |
| 下游超时 | Mock BOSS 返回 `boss_timeout`（演示号 004 订购），不编造成功 |
| 菜单 5 金额充值 | 仅 30/50/100/200，预付 + Y 确认；后付直接拒绝 |

分类器若返回不在内置+registry 白名单里的 intent（含 `subscribe_offer`），一律 `out_of_scope`。

## 4. 配置助手

厅内配置与 BOSS 合同分开：

- **指令草案**：自然语言 → 映射到**已有意图**（内置或已写入的自定义意图）→ 冲突改派 → 人审写入 catalog。已占用且意图相同则 `already_configured`，不必重复写。
- **新增意图**：接口描述 + 入参/出参 → 生成意图名、Mock 出参、短信模板 → 人审同时写 `intents.json` 与 catalog。不保存真实 URL，执行走 Mock。

新业务若没有工具和策略，指令草案应 `blocked`，引导走「新增意图」，避免幻觉出 CRM 字段。

## 5. 评测

`data/eval_set.json` 分层：规则、确认、套餐拒绝、口语、越权/编造、菜单、语言、充值卡、资费 2way、金额充值、下游失败。断言 intent、tools、是否误办理。敏感工具在确认前不得出现。

无 Key 时启发式必须能跑完全集，保证 Demo 可离线。
